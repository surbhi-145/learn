
# 🐍 Python Threading: Comprehensive Notes

## 1. Thread Fundamentals & Lifecycle

* **Main Thread:** All execution begins in the "**main**" thread (the process launched by the Python interpreter).
* **Creation Methods:**
    * **By `Thread` Object:** Use `threading.Thread(target=func, args=...)`.
        * `mythread.start()` begins execution.
        * **`mythread.join()`** makes the calling thread **wait** for the worker thread to complete.
    * **By Subclassing `Thread`:** Create a class inheriting from `threading.Thread`.
        * Thread logic must be placed inside the overridden **`run()`** method.
        * If `__init__` is overridden, **`super().__init__()`** **must** be called. Arguments passed to the constructor do **not** automatically go to `run()`.

---

## 2. Daemon Threads (Expendable Tasks)

* A **daemon thread** (`daemon=True`) runs in the background but is **non-critical**.
* **Crucial Behavior:** The Python program **will exit** if only daemon threads remain, **abruptly terminating** them, regardless of their progress.
* The program **waits** for all **non-daemon** threads to finish.

---

## 3. Synchronization Primitives

These tools manage concurrent access and coordinate threads, essential for **data integrity** due to the **Global Interpreter Lock (GIL)**.

### 3.1. Locks (Mutual Exclusion) 🔒

| Primitive | Purpose | Key Behavior |
| :--- | :--- | :--- |
| **`Lock` (Mutex)** | Used for **mutual exclusion**. Only one thread can acquire it to enter a critical section. | Must be released by the thread that acquired it. Susceptible to **deadlocks**. |
| **`RLock` (Re-entrant Lock)** | Allows the **same thread** to acquire it multiple times without deadlocking (e.g., in recursive calls). | Must be released the same number of times it was acquired, **only by the owning thread**. Releasing from another thread raises a `RuntimeError`. |

### 3.2. Coordination & Signaling

| Primitive | Purpose | Key Methods & Behavior |
| :--- | :--- | :--- |
| **`Condition` Variable** | Enables threads to **wait for a specific predicate** to become true, providing mutual exclusion + a waiting mechanism. Superior to busy waiting (polling). | `wait()` **releases the internal lock** and sleeps; `notify()`/`notify_all()` wakes up waiting threads. |
| **`Semaphore`** | A **counter-based** primitive ($\text{Semaphore}(n)$) for signaling or limiting resource access. | `acquire()` **decrements** the counter (waits if $\le 0$); `release()` increments the counter. |
| **`Event`** | The simplest primitive, using a **boolean flag** for simple "go/stop" signaling. | `set()`/`clear()` change the flag. `wait()` **blocks** until the flag is `True`. **Waiting does not change the flag's state.** |
| **`Barrier`** | Forces a group of $N$ threads to **wait for each other** to reach a specific point before all are released simultaneously. | `barrier.wait()` blocks the thread until $N$ calls have been made. |

## 4. Advanced Tools & Constraints

### 4.1. Timer ⏱️

* A specialized thread used to execute a function **once after a specified delay** without blocking the main thread.
* **Creation:** `threading.Timer(delay, function, args=...)`.

### 4.2. The Global Interpreter Lock (GIL) 🛑

* **Core Constraint:** A **mutex** held by the interpreter, ensuring only **one Python thread executes bytecode at a time**, even on multi-core CPUs.
* **Impact:**
    * **I/O-Bound Tasks:** Threads are effective because the **GIL is released** during I/O wait times, allowing true concurrency.
    * **CPU-Bound Tasks:** Threads provide **no true parallelism**. For speed, the **`multiprocessing`** module (separate processes) must be used.
* **Significance:** Synchronization primitives like `Lock` are still vital for preventing **race conditions in data manipulation**, even though the GIL limits execution parallelism.
